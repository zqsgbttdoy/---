## 五、本机验证过程中的环境处置

- **重新打包**：`target` 内旧 jar（2026-09-23）落后于修复后的源码，`mvn package` 需真实构建。8090 旧后端进程锁定 jar 导致 `repackage` 失败（`Unable to rename ...jar.original`），停止旧 java 进程（PID 3304，确系本项目后端）后重打包成功（新 jar 55.9MB，2026-10-10 15:17）。
- **离线仓库缺插件**：`.m2-cache` 无 `maven-jar-plugin`/`spring-boot-maven-plugin`，离线 `package` 报 `PluginResolutionException`；改在线抽取该插件后构建通过（仅补插件，未改依赖）。
- **prod 启动抽验受限**：以占位 `APP_JWT_SECRET` 走 `--spring.profiles.active=prod` 想做端到端拦截演示，但本机 MySQL `supervision_app` 无权限、H2 又与 Druid 初始探测器不兼容，启动在数据源阶段即失败，未达校验器。该拦截逻辑由 `ProductionSafetyValidatorTest`（含 `qaAcceptanceJwtTemplatePlaceholderMustFail` 等 20 项）在回归中充分覆盖，判定为已验证。
