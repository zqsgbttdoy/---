# 监理现场管理系统 · 生产环境部署指南

> 适用版本：supervision-site-management 1.0.0 ｜ 目标系统：Ubuntu 22.04 LTS 64 位（与 `deploy/` 下脚本一致）
> 约定：所有服务器命令均在 **bash** 中执行；`<尖括号>` 内容需替换为真实值；每节末尾附 ✅成功判据 / ❌失败处理。

---

## 0. 上线前必读（4 项阻塞条件）

| # | 事项 | 说明 |
|---|------|------|
| 1 | **域名 + ICP 备案** | 中国大陆云服务器的 80/443 端口对未备案域名会被拦截，HTTPS 证书签发与小程序合法域名都依赖它。备案通常需 1~3 周，请最先办理。 |
| 2 | **种子账号默认密码为 `123456`** | `schema.sql` 内置的 admin 及演示人员（王总监等）BCrypt 哈希经核验均对应 `123456`。上线后**第一件事**就是修改 admin 密码并停用演示账号（见 3.8）。 |
| 3 | **后端默认监听 0.0.0.0:8080** | `application.yml` 未设置 `server.address`。本指南通过环境变量 `SERVER_ADDRESS=127.0.0.1` 让后端只监听本机，再加安全组/防火墙双重屏蔽。 |
| 4 | **小程序 baseUrl** | `miniprogram/config.js` 当前为 `http://127.0.0.1:8081`，正式发布前必须改为 `https://<你的域名>`（不带 `/api`、不带结尾 `/`），并在微信公众平台配置合法域名。 |

## 1. 技术栈说明

| 层 | 技术 | 版本 / 说明 |
|----|------|------------|
| 后端语言 | Java | **17**（运行时需 JRE 17） |
| 后端框架 | Spring Boot | 3.2.5（内嵌 Tomcat，打包为可执行 fat jar） |
| 持久层 | Spring Data JPA / Hibernate 6 | 生产 `ddl-auto: validate`（**不自动建表**，必须先执行 SQL） |
| 连接池 | Alibaba Druid | 1.2.22（生产 max-active=50） |
| 认证 | jjwt（HS256 JWT） | 0.12.5，令牌默认 24 小时有效 |
| 密码加密 | spring-security-crypto BCrypt | — |
| JSON | fastjson2 / Jackson | 2.0.47 |
| 日志 | Logback（logback-spring.xml） | 按天+50MB 滚动，保留 30 天，上限 2GB |
| PC 前端 | 原生 HTML + 内联 CSS + 原生 JavaScript | 26 个静态页 + `assets/`（app.js、field-records.js、responsive.css、style.css），**无构建步骤** |
| 移动端 | 微信小程序原生（WXML/WXSS/JS） | 支持离线草稿、自动重试同步 |
| 数据库 | **MySQL 8.0**（InnoDB，utf8mb4） | 共 24 张表；Ubuntu 22.04 apt 源自带 8.0.x |
| Web 服务器 | Nginx | Ubuntu 22.04 apt 源 1.18+；负责 HTTPS、静态托管、`/api/` 反向代理、登录限频 |
| 文件存储 | 本地磁盘 | `APP_UPLOAD_DIR`（默认 `/opt/supervision/uploads`），通过 HMAC 签名短链受控访问 |
| 运维组件 | systemd、certbot、ufw、fail2ban、cron、mysqldump | 均为系统包，无需额外中间件 |

> **不依赖** Redis、消息队列、Elasticsearch、Docker。单机即可完整运行。

**请求链路**：
```
浏览器/小程序 ──HTTPS──▶ Nginx :443 ──┬─ /            → /opt/supervision/static（静态页）
                                      ├─ /api/auth/login → 限频 10 次/分/IP → 127.0.0.1:8080
                                      ├─ /api/         → 127.0.0.1:8080（Spring Boot，context-path=/api）
                                      └─ /uploads/、/api/uploads/ → 403（附件只能走签名链接）
Spring Boot ──JDBC──▶ MySQL 127.0.0.1:3306/supervision_db
```

## 2. 服务器选型建议

### 2.1 资源估算依据

| 资源 | 估算 |
|------|------|
| 内存 | JVM 堆 1~2G + 非堆约 0.4G；MySQL（buffer pool 512M~2G）约 0.8~2.5G；Nginx+系统约 0.4G |
| CPU | 业务为表单录入/查询/报表导出，峰值在早晚集中填报与导出 Excel 时，2 核可支撑约 100 名活跃用户 |
| 磁盘 | 主要增量是现场照片：例如 20 人 × 10 张/天 × 2MB ≈ **400MB/天 ≈ 12GB/月**；数据库本身每年通常 < 5GB |
| 带宽 | 单文件上限 50MB；3Mbps ≈ 375KB/s，一张 5MB 照片需约 13 秒，多人同时上传会排队 |

### 2.2 配置对比

| 项目 | 最低配置（≤50 人试运行） | 推荐配置（50~300 人正式运行） |
|------|------------------------|-----------------------------|
| 阿里云 | ECS 通用型 **2 核 4G**（如 g7/u1 系列） | ECS 通用型 **4 核 8G** |
| 腾讯云 | CVM 标准型 S5/SA3 **2 核 4G** | CVM 标准型 **4 核 8G** |
| 系统盘 | 40GB ESSD | 40~60GB ESSD |
| 数据盘 | 100GB ESSD（挂载到 `/opt/supervision`） | 200GB+ ESSD，可在线扩容 |
| 带宽 | 固定 5Mbps | 按流量计费，峰值 50~100Mbps（上传照片体验明显更好） |
| JVM 参数 | `-Xms1G -Xmx2G` + 2G swap | `-Xms2G -Xmx4G` |
| MySQL buffer pool | 512M | 2G |
| 数据库形态 | 与应用同机 | 同机，或改用 RDS MySQL 8.0 基础版（自动备份、主备） |
| 备份 | 本机 mysqldump + 每周云盘快照 | 本机 mysqldump + 每日快照 + OSS 异地 |

**选型理由**：
- 本系统是单体 Spring Boot + 单库，没有缓存/队列，**内存是第一瓶颈**：2 核 2G 放不下 JVM + MySQL，4G 是可用下限，8G 才有余量做报表导出和 MySQL 缓存。
- 照片附件存在本地盘，**数据盘与系统盘分离**可以独立扩容和快照，重装系统也不会丢附件。
- 地域选离施工项目最近的区域（华东/华南/华北），实例与 RDS（如使用）放在同一可用区。

## 3. 详细部署步骤

### 3.0 本地打包并上传（在 Windows 开发机执行）

前提：本机已安装 JDK 17。

```powershell
cd "<项目目录>\补后端"
.\打包发布.bat
# 产物：dist\supervision-release-1.0.0.zip（含 backend\jar、sql\、frontend\、deploy\、docs\）

scp .\dist\supervision-release-1.0.0.zip root@<服务器公网IP>:/tmp/
```

✅ 成功：`打包发布.bat` 输出 `[5/5] 打包完成`；`scp` 进度到 100%。
❌ 失败：
- 提示找不到 mvnw.cmd → 确认在 `补后端` 目录下执行；
- Maven 编译失败 → 先在 `补后端\backend` 执行 `.\mvnw.cmd -v` 确认 JDK 17；
- `scp` 超时 → 检查安全组是否放行 22 端口、IP 是否正确。

### 3.1 服务器环境准备

**登录服务器后，先设置本次会话变量（每次新开 SSH 都要重新执行）：**
```bash
export DOMAIN=<你的域名，如 jl.example.com>
```

**① 基础设置与软件安装**
```bash
sudo timedatectl set-timezone Asia/Shanghai
sudo apt-get update
sudo apt-get install -y openjdk-17-jre-headless nginx mysql-server unzip curl
sudo systemctl enable --now mysql nginx
java -version; mysql --version; nginx -v
```
✅ 成功：`java -version` 显示 `17.x`；`mysql --version` 显示 `8.0.x`；`systemctl is-active mysql nginx` 输出两行 `active`。
❌ 失败：apt 报锁占用（`Could not get lock`）→ 等待 1~2 分钟（云主机首次开机在自动更新）后重试。

**② （仅 4G 内存机器）添加 2G swap，防止内存不足被系统杀进程**
```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h
```
✅ 成功：`free -h` 的 Swap 行显示 `2.0Gi`。

**③ （可选，推荐）挂载数据盘到 /opt/supervision**
```bash
lsblk
# 找到没有 MOUNTPOINT 的新盘，例如 vdb。⚠️ 下一条会清空该盘，只能对全新空盘执行！
sudo mkfs.ext4 /dev/vdb
sudo mkdir -p /opt/supervision
echo "UUID=$(sudo blkid -s UUID -o value /dev/vdb) /opt/supervision ext4 defaults,nofail 0 2" | sudo tee -a /etc/fstab
sudo mount -a
df -h /opt/supervision
```
✅ 成功：`df -h` 显示 `/opt/supervision` 挂在 `/dev/vdb` 上。
❌ 失败：`mount -a` 报错 → 用 `sudo nano /etc/fstab` 删除刚追加的那一行，确认盘符后重做，**不要在 fstab 错误时重启**。

**④ 创建运行用户与目录**
```bash
sudo useradd --system --no-create-home --shell /usr/sbin/nologin supervision
sudo mkdir -p /opt/supervision/{backend,uploads,logs,backups,static,certs,release}
sudo chown -R supervision:supervision /opt/supervision
sudo chmod 755 /opt/supervision /opt/supervision/static
sudo chmod 750 /opt/supervision/uploads
sudo chmod 700 /opt/supervision/backups /opt/supervision/certs
ls -l /opt/supervision
```
✅ 成功：7 个目录属主均为 `supervision`。
❌ 失败：`useradd: user 'supervision' already exists` → 已创建过，忽略即可。

**⑤ 解压发布包**
```bash
sudo unzip -o /tmp/supervision-release-1.0.0.zip -d /opt/supervision/release
ls /opt/supervision/release
```
✅ 成功：看到 `backend  deploy  docs  frontend  sql` 五个目录。
❌ 失败：出现 `appears to use backslashes as path separators` 警告 → 无害（Windows 打包特性），只要五个目录都在即可。

**⑥ MySQL 基础参数（字符集、仅本机监听、内存）**
```bash
sudo tee /etc/mysql/mysql.conf.d/zz-supervision.cnf >/dev/null <<'EOF'
[mysqld]
character-set-server = utf8mb4
collation-server     = utf8mb4_unicode_ci
default-time-zone    = '+08:00'
bind-address         = 127.0.0.1
max_connections      = 200
innodb_buffer_pool_size = 512M
EOF
sudo systemctl restart mysql
sudo ss -lntp | grep 3306
```
> 4 核 8G 机器把 `512M` 改为 `2G`。

✅ 成功：`ss` 输出中 3306 只绑定 `127.0.0.1:3306`（不是 `0.0.0.0` 或 `*`）。
❌ 失败：MySQL 起不来 → `sudo tail -n 50 /var/log/mysql/error.log`，多为参数拼写错误，修正后重启。

### 3.2 数据库初始化

> Ubuntu 的 MySQL root 默认使用 `auth_socket`，用 `sudo mysql` 即可免密进入，无需 root 密码。

**① 生成数据库专用账号密码（请立刻记录到密码管理器）**
```bash
DBPWD=$(openssl rand -hex 16); echo "数据库密码：$DBPWD"
```
> 若 SSH 中断，重新执行 `DBPWD=<你记录的密码>` 即可继续。

**② 建库 + 建专用账号（仅授予增删改查）**
```bash
sudo mysql -e "CREATE DATABASE IF NOT EXISTS supervision_db DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
sudo mysql -e "CREATE USER IF NOT EXISTS 'supervision_app'@'localhost' IDENTIFIED BY '${DBPWD}'; GRANT SELECT, INSERT, UPDATE, DELETE ON supervision_db.* TO 'supervision_app'@'localhost'; FLUSH PRIVILEGES;"
```

**③ 执行建表与索引脚本（顺序不能反，索引脚本只能执行一次）**
```bash
sudo mysql --default-character-set=utf8mb4 supervision_db < /opt/supervision/release/sql/schema.sql
sudo mysql --default-character-set=utf8mb4 supervision_db < /opt/supervision/release/sql/schema-indexes.sql
```

**④ 校验**
```bash
sudo mysql -N -e "SELECT COUNT(*) FROM information_schema.tables WHERE table_schema='supervision_db';"
mysql -u supervision_app -p"${DBPWD}" supervision_db -e "SELECT id, name, phone, status FROM sys_user;"
```
✅ 成功：第一条输出 `24`；第二条能用专用账号查到 admin 等种子用户，且中文姓名不乱码。
❌ 失败：
- 表数不是 24 → 检查 `schema.sql` 执行是否有报错输出，必要时 `sudo mysql -e "DROP DATABASE supervision_db;"` 后从②重做（**仅限首次部署、库中无业务数据时**）；
- `schema-indexes.sql` 报 `Duplicate key name` → 说明已执行过，忽略；
- `Access denied for user 'supervision_app'` → 密码不一致，执行 `sudo mysql -e "ALTER USER 'supervision_app'@'localhost' IDENTIFIED BY '${DBPWD}';"`；
- 中文乱码 → 导入时漏了 `--default-character-set=utf8mb4`，删库重导。

> 等价脚本：`sudo bash /opt/supervision/release/deploy/init-database.sh <schema.sql> <schema-indexes.sql>`（交互输入密码，root 密码提示直接回车即可）。

**⑤ admin 最高权限初始化（幂等，可重复执行）**
```bash
sudo mysql --default-character-set=utf8mb4 supervision_db < /opt/supervision/release/sql/admin-full-permissions.sql
```
✅ 成功：最后输出的核验行中 `name=admin`、`status=active`、`is_admin=1`，且 `permission_total` 与 `admin_bound` 相等（首次为 31）。
❌ 失败：报 `Table ... doesn't exist` → 先完成③建表。

### 3.4 配置环境变量（敏感信息注入）

**原则**：所有密钥只存在于 `/opt/supervision/backend/supervision.env`（权限 600），由 systemd 的 `EnvironmentFile=` 注入；不写进 jar、不写进 yml、不进 Git、不出现在命令行进程参数中。

**① 从模板复制并收紧权限**
```bash
ENVF=/opt/supervision/backend/supervision.env
sudo cp /opt/supervision/release/deploy/supervision.env.example $ENVF
sudo chown supervision:supervision $ENVF
sudo chmod 600 $ENVF
```

**② 自动填入随机密钥（直接复制执行，无需手动编辑）**
```bash
sudo sed -i "s|^SPRING_DATASOURCE_PASSWORD=.*|SPRING_DATASOURCE_PASSWORD=${DBPWD}|" $ENVF
sudo sed -i "s|^APP_JWT_SECRET=.*|APP_JWT_SECRET=$(openssl rand -base64 48 | tr -d '\n')|" $ENVF
sudo sed -i "s|^APP_UPLOAD_SIGNING_SECRET=.*|APP_UPLOAD_SIGNING_SECRET=$(openssl rand -base64 48 | tr -d '\n')|" $ENVF
sudo sed -i "s|^APP_CORS_ALLOWED_ORIGINS=.*|APP_CORS_ALLOWED_ORIGINS=https://${DOMAIN}|" $ENVF
sudo sed -i "s|^APP_DEFAULT_RESET_PASSWORD=.*|APP_DEFAULT_RESET_PASSWORD=Jl$(openssl rand -hex 4)2026|" $ENVF
echo "SERVER_ADDRESS=127.0.0.1" | sudo tee -a $ENVF >/dev/null
```

**③ 校验**
```bash
sudo grep -c '请替换' $ENVF
sudo grep -E '^(SPRING_PROFILES_ACTIVE|SPRING_DATASOURCE_USERNAME|APP_CORS_ALLOWED_ORIGINS|APP_UPLOAD_DIR|SERVER_ADDRESS)=' $ENVF
sudo grep '^APP_DEFAULT_RESET_PASSWORD=' $ENVF
ls -l $ENVF
```
✅ 成功：第一条输出 `0`；`SPRING_PROFILES_ACTIVE=prod`、`APP_CORS_ALLOWED_ORIGINS=https://<域名>`、`SERVER_ADDRESS=127.0.0.1` 均存在；文件权限为 `-rw-------`。记录下重置默认密码，交给管理员。
❌ 失败：仍有 `请替换` → `sudo nano $ENVF` 手工补齐。

**变量清单**

| 变量 | 必填 | 规则（不满足则启动即失败） |
|------|------|------|
| `SPRING_PROFILES_ACTIVE` | ✅ | 固定 `prod` |
| `SPRING_DATASOURCE_USERNAME` | ✅ | `supervision_app`，禁止 root |
| `SPRING_DATASOURCE_PASSWORD` | ✅ | ≥8 位且含字母+数字，禁止 root/123456 |
| `APP_JWT_SECRET` | ✅ | ≥32 字符，不得为开发默认值/占位符 |
| `APP_UPLOAD_SIGNING_SECRET` | ✅ | ≥32 字符，**不得与 JWT 密钥相同** |
| `APP_CORS_ALLOWED_ORIGINS` | ✅ | 明确域名，含协议，逗号分隔，禁止 `*`，末尾不加 `/` |
| `APP_DEFAULT_RESET_PASSWORD` | ✅ | ≥8 位且含字母+数字，禁止 123456 |
| `APP_UPLOAD_DIR` | ✅ | `/opt/supervision/uploads` |
| `SERVER_ADDRESS` | 建议 | `127.0.0.1`，后端只监听本机 |
| `SPRING_DATASOURCE_URL` | 可选 | 使用 RDS 或非默认端口时设置 |
| `APP_JWT_EXPIRATION` | 可选 | 令牌有效期毫秒，默认 86400000（24h） |

> ⚠️ 修改 `APP_JWT_SECRET` 会使所有已登录用户立即失效（需重新登录）；修改 `APP_UPLOAD_SIGNING_SECRET` 会使已签发的附件短链失效。

### 3.5 启动后端服务（systemd + 开机自启）

```bash
sudo cp /opt/supervision/release/deploy/supervision.service /etc/systemd/system/supervision.service
# 4 核 8G 机器执行下一行，把堆内存调为 2G~4G；2 核 4G 保持默认 1G~2G
# sudo sed -i 's/-Xms1G -Xmx2G/-Xms2G -Xmx4G/' /etc/systemd/system/supervision.service
sudo systemctl daemon-reload
sudo systemctl enable --now supervision
```

等待约 30~60 秒后验证：
```bash
sudo systemctl status supervision --no-pager
sudo ss -lntp | grep 8080
curl -s -X POST http://127.0.0.1:8080/api/auth/login -H 'Content-Type: application/json' -d '{"username":"admin","password":"123456"}'; echo
```
✅ 成功：
- `status` 显示 `active (running)`，且 `enabled`；
- `ss` 显示 `127.0.0.1:8080`（**不是** `*:8080`）；
- curl 返回 `{"code":200,...,"data":{"token":"eyJ..."...}}`。

❌ 失败：
```bash
sudo journalctl -u supervision -n 100 --no-pager      # 启动期错误（含安全校验失败）
sudo tail -n 200 /opt/supervision/backend/logs/app.log  # 应用运行日志
```
| 日志关键字 | 原因 | 处理 |
|-----------|------|------|
| `生产环境启动失败：...` | 环境变量不满足安全校验 | 按提示修改 `supervision.env`，`sudo systemctl restart supervision` |
| `Schema-validation: missing table/column` | 未执行 schema.sql 或库结构是旧版本 | 回到 3.2 执行 SQL |
| `Access denied for user 'supervision_app'` | 数据库密码与 env 不一致 | 3.2 ❌ 中的 `ALTER USER` |
| `Communications link failure` | MySQL 未运行 | `sudo systemctl start mysql` |
| `Port 8080 was already in use` | 端口被占用 | `sudo ss -lntp \| grep 8080` 找到进程处理 |
| `Permission denied`（logs/uploads） | 目录属主不对 | `sudo chown -R supervision:supervision /opt/supervision/backend /opt/supervision/uploads` |
| 进程反复重启、`dmesg` 有 `Out of memory` | 内存不足 | 加 swap（3.1②）或降低 `-Xmx` |

### 3.6 配置 Nginx（反向代理 + 静态托管 + HTTPS）

**① 安装站点配置并替换域名**
```bash
sudo cp /opt/supervision/release/deploy/nginx-supervision.conf /etc/nginx/conf.d/supervision.conf
sudo sed -i "s/your-domain.com/${DOMAIN}/g" /etc/nginx/conf.d/supervision.conf
# 移除 Ubuntu 默认站点的软链接，避免抢占 80 端口
sudo rm -f /etc/nginx/sites-enabled/default
```

**② 申请证书（二选一）**

**方案 A：Let's Encrypt 免费证书（自动续期，推荐）** —— 前提：域名已备案并解析到本机，安全组放行 80
```bash
sudo apt-get install -y certbot
sudo certbot certonly --standalone -d ${DOMAIN} --agree-tos -m <你的邮箱> --non-interactive \
  --pre-hook "systemctl stop nginx" --post-hook "systemctl start nginx"
sudo sed -i "s|/opt/supervision/certs/fullchain.pem|/etc/letsencrypt/live/${DOMAIN}/fullchain.pem|; s|/opt/supervision/certs/privkey.pem|/etc/letsencrypt/live/${DOMAIN}/privkey.pem|" /etc/nginx/conf.d/supervision.conf
sudo certbot renew --dry-run
```

**方案 B：阿里云/腾讯云控制台下载的证书（Nginx 格式）**
```bash
# 在 Windows 本机执行：
scp .\<证书>.pem .\<证书>.key root@<服务器IP>:/tmp/
# 在服务器执行：
sudo mv /tmp/<证书>.pem /opt/supervision/certs/fullchain.pem
sudo mv /tmp/<证书>.key /opt/supervision/certs/privkey.pem
sudo chmod 600 /opt/supervision/certs/*
```
> 云厂商免费证书有效期较短（当前多为 3 个月），需在到期前手动替换并 reload。

**③ 校验并加载**
```bash
sudo nginx -t
sudo systemctl reload nginx
curl -sI http://${DOMAIN} | head -n 1
curl -sI https://${DOMAIN}/login.html | head -n 1
```
✅ 成功：`nginx -t` 输出 `syntax is ok` 和 `test is successful`；HTTP 返回 `301`，HTTPS 返回 `200`。
❌ 失败：
- `cannot load certificate` → 证书路径错误，`sudo grep ssl_certificate /etc/nginx/conf.d/supervision.conf` 核对；
- certbot 报 `Timeout during connect` → 安全组未放行 80、域名未解析到本机或备案未通过；
- `nginx -t` 报 `duplicate default server` / 80 端口冲突 → 确认已删除 `sites-enabled/default`。

### 3.7 安全加固

**① 云安全组（在阿里云/腾讯云控制台配置入方向）**

| 端口 | 来源 | 说明 |
|------|------|------|
| 22 | **仅你的办公/家庭公网 IP** | SSH |
| 80 | 0.0.0.0/0 | 仅用于跳转 HTTPS 和证书验证 |
| 443 | 0.0.0.0/0 | 业务访问 |
| 3306、8080 及其他 | **不开放** | 数据库与后端只允许本机访问 |

**② 系统防火墙 ufw**（⚠️ 必须先放行 SSH 再启用，否则会断开）
```bash
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw --force enable
sudo ufw status verbose
```
✅ 成功：状态 `active`，仅列出 `OpenSSH` 与 `Nginx Full`（80/443）。
❌ 失败：启用后 SSH 断开 → 通过云控制台「远程连接/VNC」登录执行 `sudo ufw allow OpenSSH`。

**③ SSH 改为密钥登录**

在 Windows 本机（PowerShell）：
```powershell
ssh-keygen -t ed25519
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@<服务器IP> "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"
ssh root@<服务器IP>      # 确认无需密码即可登录
```

确认密钥登录成功后，在服务器上：
```bash
sudo tee /etc/ssh/sshd_config.d/01-supervision-hardening.conf >/dev/null <<'EOF'
PubkeyAuthentication yes
PasswordAuthentication no
PermitRootLogin prohibit-password
MaxAuthTries 3
EOF
sudo sshd -t && sudo systemctl restart ssh
sudo sshd -T | grep -E '^(passwordauthentication|permitrootlogin)'
```
> 文件名必须用 `01-` 前缀：sshd 以首次出现的值为准，云镜像自带的 `50-cloud-init.conf` 往往写着 `PasswordAuthentication yes`，用 `90-` 前缀会被它覆盖而静默失效。

✅ 成功：`sshd -T` 输出 `passwordauthentication no`、`permitrootlogin without-password`；**保持当前窗口不关**，另开新窗口能用密钥登录。
❌ 失败：新窗口登录不上 → 在旧窗口执行 `sudo rm /etc/ssh/sshd_config.d/01-supervision-hardening.conf; sudo systemctl restart ssh` 回退。

**④ fail2ban（SSH 暴力破解 + 登录接口持续触发限频的 IP 自动封禁）**
```bash
sudo apt-get install -y fail2ban
sudo tee /etc/fail2ban/jail.local >/dev/null <<'EOF'
[DEFAULT]
bantime  = 3600
findtime = 600
maxretry = 5
backend  = systemd
ignoreip = 127.0.0.1/8 <你的办公公网IP>

[sshd]
enabled = true

[nginx-limit-req]
enabled  = true
backend  = auto
logpath  = /var/log/nginx/error.log
EOF
sudo systemctl enable --now fail2ban
sudo systemctl restart fail2ban
sudo fail2ban-client status
```
✅ 成功：`Jail list:` 包含 `nginx-limit-req, sshd`。
❌ 失败：`systemctl status fail2ban` 报配置错误 → 检查 `ignoreip` 是否保留了尖括号占位符，没有办公 IP 就删除该部分。

**⑤ 自动安全更新**
```bash
sudo apt-get install -y unattended-upgrades
sudo dpkg-reconfigure -f noninteractive unattended-upgrades
cat /etc/apt/apt.conf.d/20auto-upgrades
```
✅ 成功：两行值均为 `"1"`。

**⑥ 自检汇总**
```bash
sudo ss -lntp | grep -E ':(22|80|443|3306|8080) '
```
✅ 成功：22/80/443 对外监听；**3306 和 8080 只出现在 `127.0.0.1`**。

> 等价脚本：`sudo bash /opt/supervision/release/deploy/enable-hardening.sh`（已同步修正为 `01-` 前缀）。

### 4.2 常见问题排查表

| 现象 | 常见原因 | 排查命令 | 处理 |
|------|---------|---------|------|
| **502 Bad Gateway** | 后端未启动 / 正在启动 / 已崩溃 | `systemctl status supervision`；`ss -lntp \| grep 8080`；`tail /var/log/nginx/error.log`（`connect() failed (111)`） | 启动中等 1 分钟；崩溃看 3.5 ❌ 表 |
| **504 Gateway Timeout** | 大报表导出超过 120 秒 | `grep proxy_read_timeout /etc/nginx/conf.d/supervision.conf` | 适当调大 `proxy_read_timeout` 后 reload |
| **数据库连接失败** | MySQL 未运行 / 密码错误 / 库不存在 | `systemctl status mysql`；`mysql -u supervision_app -p supervision_db -e 'SELECT 1'` | 启动 MySQL；`ALTER USER` 重设密码并同步 env |
| `Public Key Retrieval is not allowed` | 自行把 URL 改成了 `useSSL=false` | `sudo grep DATASOURCE_URL /opt/supervision/backend/supervision.env` | 保持默认 `useSSL=true`，或在 URL 追加 `allowPublicKeyRetrieval=true` |
| **端口占用** | 旧进程未退出 / 手工 `java -jar` 残留 | `sudo ss -lntp \| grep 8080` | `sudo kill <PID>` 后 `systemctl start supervision` |
| 启动报 `生产环境启动失败` | env 变量不合规 | `journalctl -u supervision -n 50` | 按提示修改 env |
| 启动报 `Schema-validation` | 表结构缺失或版本不一致 | 同上 | 执行 schema 或升级迁移脚本 |
| **登录返回 429** | 登录限频：每 IP 10 次/分 | `grep limiting /var/log/nginx/error.log` | 工地/办公室共用出口 IP 时，把 conf 中 `rate=10r/m` 调到 `30r/m` |
| 登录后马上跳回登录页 | JWT 密钥被修改 / 账号被停用 / 服务器时间偏差 | `timedatectl`；`app.log` 搜 401 | 重新登录；检查用户状态；开启 NTP |
| **413 Request Entity Too Large** | 上传超过 100MB | — | 后端单文件上限 50MB、单请求 100MB，拆分上传 |
| 上传 500 / Permission denied | uploads 目录属主错误 | `ls -ld /opt/supervision/uploads` | `sudo chown -R supervision:supervision /opt/supervision/uploads` |
| 页面 403 Forbidden | 静态文件权限不足 | `namei -l /opt/supervision/static/login.html` | 按 3.3 重新 chmod |
| 页面 404 | 静态文件未复制 / 访问路径错误 | `ls /opt/supervision/static` | 按 3.3 重新复制 |
| 发版后页面仍是旧版 | 浏览器缓存 | — | 已配置 html/js/css 不缓存，Ctrl+F5 强刷；仍旧则检查是否复制到正确目录 |
| CORS 报错 | 前端与 API 不同域，且来源未加入白名单 | `grep CORS /opt/supervision/backend/supervision.env` | 精确填写 `https://域名`（无结尾 `/`），多个用逗号分隔 |
| 中文乱码 | 导入 SQL 未指定 utf8mb4 | `sudo mysql -e "SHOW CREATE DATABASE supervision_db"` | 重建库并带 `--default-character-set=utf8mb4` 导入 |
| 小程序提示“不在合法域名列表” | 未配置服务器域名 | — | 公众平台 → 开发管理 → 服务器域名：request / uploadFile / downloadFile 均填 `https://域名` |
| 证书过期 | 续期失败 | `sudo certbot certificates` | `sudo certbot renew`；云厂商证书手动替换 |
| 脚本报 `$'\r': command not found` | 脚本在 Windows 编辑后带 CRLF | `file xxx.sh` | `sed -i 's/\r$//' xxx.sh` |
| 进程被系统杀掉 | 内存不足（OOM） | `dmesg -T \| grep -i 'killed process'` | 加 swap、降 `-Xmx` 或升配 |

## 5. 运维手册要点

### 5.1 日常启停

| 操作 | 命令 |
|------|------|
| 后端 状态/启动/停止/重启 | `sudo systemctl status\|start\|stop\|restart supervision` |

### 5.2 日志位置

| 日志 | 位置 / 命令 |
|------|------------|
| 应用日志（INFO 及以上） | `/opt/supervision/backend/logs/app.log`（按天滚动 `app.YYYY-MM-DD.N.log`，保留 30 天） |
| 启动失败 / WARN 以上 | `sudo journalctl -u supervision -f` |
| Nginx 访问 / 错误 | `/var/log/nginx/access.log`、`/var/log/nginx/error.log` |

### 5.3 备份

**① 配置数据库备份凭据**（`DBPWD` 为 3.2 记录的密码）
```bash
sudo tee /opt/supervision/backend/.backup.cnf >/dev/null <<EOF
[client]
user=supervision_app
password=${DBPWD}
host=localhost
EOF
sudo chown supervision:supervision /opt/supervision/backend/.backup.cnf
sudo chmod 600 /opt/supervision/backend/.backup.cnf
sudo bash /opt/supervision/backend/backup.sh
```
✅ 成功：输出 `备份成功：/opt/supervision/backups/supervision_db_xxx.sql.gz`。
❌ 失败：`PROCESS privilege` 报错 → 确认使用的是新版 backup.sh（已加 `--no-tablespaces`）。

**② 定时任务**（`sudo crontab -e`，追加以下两行）
```
0 2 * * * /bin/bash /opt/supervision/backend/backup.sh >> /opt/supervision/logs/backup.log 2>&1
30 3 * * 0 tar czf /opt/supervision/backups/uploads_$(date +\%Y\%m\%d).tar.gz -C /opt/supervision uploads && find /opt/supervision/backups -name 'uploads_*.tar.gz' -mtime +60 -delete
```
含义：每天 02:00 备份数据库（保留 30 天）；每周日 03:30 打包附件（保留 60 天）。

**③ 异地/快照（强烈建议）**：备份与数据在同一台机器上不能防止整机故障。
- 云控制台为系统盘和数据盘创建**自动快照策略**（每日一次，保留 7~14 天）；
- 或使用 `ossutil` / `coscmd` 每日把 `/opt/supervision/backups` 同步到对象存储。
