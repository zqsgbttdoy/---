# 一、系统功能说明

监理现场管理系统是一套面向建设工程监理企业的现场监理业务管理软件，覆盖监理项目从进场到竣工全过程的日常业务活动。系统以项目台账为中心，围绕监理日记、监理日志、安全日志、日常巡检、旁站巡检、监理通知单、工作联系单、会议纪要、监理月报等核心监理文书，提供在线填报、审批流转、统计分析与资料归档能力；同时内置基于 RBAC 模型的用户、角色、权限、部门管理体系，以及消息中心、操作日志等支撑功能。系统后端共 22 个业务控制器、111 个 REST 接口，数据库 21 张数据表，前端 26 个功能页面。

## 1.1 认证与安全模块

提供系统统一登录入口。用户使用手机号与密码登录，服务端采用 BCrypt 算法校验密码摘要，校验通过后签发 JWT（JSON Web Token，HS256 算法）访问令牌；前端后续请求通过 Authorization 请求头携带令牌完成身份认证。模块同时提供退出登录、获取当前登录用户信息、修改密码等功能，登录口令全程不以明文存储。

## 1.2 工作台模块

登录后的系统首页驾驶舱。汇总展示当前用户可见的项目数量、各类监理业务单据（日记、日志、巡检、通知单等）的数量统计与待办事项，提供各业务模块的快捷入口，帮助监理人员快速掌握项目整体情况。

## 1.3 项目台账模块

对监理项目进行全生命周期台账管理，支持项目的新增、修改、删除与分页查询，记录项目名称、编号、建设单位、施工单位、监理单位、工期、状态等信息，是全系统各业务单据的项目归属基础。

## 1.4 组织与权限模块（用户/角色/权限/部门）

实现基于 RBAC（基于角色的访问控制）模型的组织权限体系。部门管理支持树形部门结构维护；用户管理（人员管理）支持监理人员档案的增删改查、状态启停用与密码重置；角色管理支持角色定义及角色-权限绑定；权限管理支持按模块维护权限点。用户通过用户-角色、角色-权限两级关联获得系统操作权限。

## 1.5 监理日记模块

监理人员按日填写个人监理日记，记录当日天气、施工部位、施工情况、监理工作情况、存在问题及处理意见等，支持新增、修改、删除、分页查询与审批流转（提交/审批通过/退回），并提供日记统计与日记报表页面进行汇总分析。

## 1.6 监理日志模块

以项目为单位按日填写项目监理日志，内容涵盖施工动态、监理巡视旁站情况、验收与材料进场情况、安全文明施工情况等，支持增删改查与审批流转，并配套日志统计页面按时间区间汇总。

## 1.7 安全日志模块

专项记录施工现场安全监理工作，包括安全巡查情况、危险性较大分部分项工程管控、安全隐患及整改闭环情况等，支持增删改查与审批流转，并配套安全日志统计页面进行安全态势分析。

## 1.8 巡检管理模块（日常巡检/旁站巡检）

日常巡检记录监理人员对施工现场的日常检查情况，包括检查部位、检查内容、发现问题与处理结果；旁站巡检针对关键部位、关键工序的旁站监理进行记录，包括旁站部位、起止时间、施工情况与监理意见。两类记录均支持增删改查与分页检索。

## 1.9 监理文书模块（通知单/联系单/会议纪要）

监理通知单用于向施工单位签发整改、停工等监理指令并跟踪回复闭环；工作联系单用于参建各方之间的日常工作联系与事项沟通；会议纪要用于记录监理例会、专题会议的议题、决议与参会人员。三类文书均支持编号管理、增删改查与状态流转。

## 1.10 分部分项数据库模块

维护工程分部分项划分标准数据库，按单位工程-分部工程-分项工程层级组织，为巡检、验收等业务提供标准化的部位与工序选择依据，支持条目的增删改查与检索。

## 1.11 监理月报模块

按月编制项目监理月报，汇总当月工程进度、质量、安全、造价控制情况及下月监理工作计划，支持月报的新增、修改、删除、分页查询与在线查阅。

## 1.12 项目资料模块（项目文档/文件上传）

项目文档管理支持项目过程资料的分类上传、检索与下载管理；文件上传服务提供统一的附件上传能力，采用扩展名白名单校验、防路径遍历、UUID 重命名与按日期分目录存储等安全加固策略，上传成功后返回统一的文件访问地址。

## 1.13 消息中心模块

提供站内消息能力，业务审批、指派等操作自动向相关人员发送消息，用户可查看消息列表、未读数量并进行已读标记，保障业务流转信息及时触达。

## 1.14 操作日志模块

自动记录用户在系统中的关键操作（操作人、动作、模块、详情、IP、时间），提供分页查询与追溯能力，满足审计合规要求。

## 1.15 工作标准配置模块

维护监理工作标准与流程配置（工作标准配置、流程管理），支持标准条目的增删改查，用于规范监理作业流程与考核依据。

# 二、技术架构描述

## 2.1 总体分层架构

系统采用前后端分离的 B/S 架构。后端基于 Spring Boot 构建 REST API 服务，代码包根为 com.supervision，采用经典四层架构：

- Controller 层（controller 包）：接收 HTTP 请求、参数校验、调用业务服务并返回统一响应，共 22 个控制器；
- Service 层（service 包）：承载业务逻辑，包括审批流转、编号生成、统计汇总、消息触发等；
- Repository 层（repository 包）：基于 Spring Data JPA 的数据访问层，负责与 MySQL 数据库交互；
- Entity 层（entity 包）：JPA 实体，与数据库表一一映射。

前端为 26 个纯静态 HTML 页面（无前端框架，内联 CSS），通过公共脚本 assets/app.js 以 fetch 方式调用后端 /api 接口，完成数据渲染与交互。

## 2.3 认证与安全机制

系统采用 JWT（JSON Web Token）无状态认证方案：用户登录时，服务端使用 BCrypt 算法对提交口令与数据库中存储的密码摘要进行比对，校验通过后使用 HS256 算法签发带有效期的 JWT 访问令牌；前端将令牌保存在浏览器本地，后续每次请求通过 Authorization: Bearer <token> 请求头携带。服务端拦截器统一校验令牌合法性与有效期，未通过认证的请求返回 HTTP 401，前端捕获后自动跳转登录页。

其他安全设计：用户口令仅以 BCrypt 摘要形式存储，全程不落明文；文件上传采用扩展名白名单、防路径遍历校验与 UUID 重命名存储；关键操作写入操作日志（操作人、动作、模块、IP、时间）供审计追溯；接口权限基于 RBAC 角色权限模型控制。

## 2.4 部署形态

生产环境采用 Nginx + Spring Boot + MySQL 的经典部署形态：

- Nginx：托管全部静态 HTML 页面（根路径 /），并将 /api/ 前缀请求反向代理至后端 8080 端口；
- Spring Boot 应用：以可执行 JAR（supervision-site-management-1.0.0.jar）方式运行，由 systemd 管理进程生命周期；
- MySQL 8.0：独立数据库服务，通过 Druid 连接池访问；数据库结构由 schema.sql 初始化、schema-indexes.sql 补充复合索引；
- 配置外部化：数据库连接等配置支持通过 SPRING_DATASOURCE_* 等环境变量覆盖，无需修改程序包即可适配不同环境。

# 三、数据库设计文档

数据库名为 supervision_db，字符集 utf8mb4、排序规则 utf8mb4_unicode_ci，存储引擎 InnoDB。共 21 张数据表，按前缀划分为两类：sys_ 前缀为系统支撑表（组织、权限、日志、消息等），biz_ 前缀为监理业务表（日记、日志、巡检、文书等）。各表统一包含自增主键 id 与 create_time / update_time 审计字段；在单列索引基础上另行维护 7 条复合索引（schema-indexes.sql）以优化高频列表查询。

# 四、接口文档

## 4.1 统一接口契约

全部接口以 /api 为统一前缀，请求与响应均为 JSON 格式。除登录接口外，所有接口须在请求头携带 Authorization: Bearer <JWT令牌>；令牌缺失、非法或过期时返回 HTTP 401，前端统一拦截并跳转登录页。

统一响应结构 ApiResponse：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | int | 业务状态码，200 表示成功，其余为业务错误码 |
| message | string | 提示信息 |
| data | object | 业务数据载荷，失败时可为空 |

分页查询统一返回 PageResult（置于 ApiResponse.data 中）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| list | array | 当前页数据列表 |
| total | long | 满足条件的记录总数 |
| pageNum | int | 当前页码（从 1 开始） |
| pageSize | int | 每页条数 |

# 五、用户操作手册

## 5.1 登录入口说明

在浏览器地址栏输入系统访问地址（如 http://服务器地址/），系统自动进入登录页。输入管理员分配的手机号与密码，点击"登录"即可进入系统工作台。首次登录后建议通过"修改密码"功能更换初始密码。登录状态失效（令牌过期）时，任何操作都会自动跳回登录页，重新登录即可。

系统共 26 个功能页面，以下按页面分节说明操作方法。

### 5.2.1 日常巡检（daily-inspection.html）

- 进入路径：左侧菜单"巡检管理 → 日常巡检"
- 主要功能：日常巡检记录的增删改查
- 操作步骤：
1. 按项目、日期筛选巡检记录
2. 点击"新增"填写检查部位、检查内容、发现问题与处理结果
3. 点击"编辑"/"删除"维护记录

### 5.2.2 部门管理（department-management.html）

- 进入路径：左侧菜单"系统管理 → 部门管理"
- 主要功能：树形部门结构维护
- 操作步骤：
1. 查看部门列表及层级关系
2. 点击"新增"填写部门名称、上级部门、负责人后保存
3. 点击"编辑"/"删除"维护已有部门

### 5.2.3 日记报表（diary-report.html）

- 进入路径：左侧菜单"监理业务 → 日记报表"
- 主要功能：监理日记报表查阅与导出打印
- 操作步骤：
1. 选择项目与日期范围生成报表
2. 在线查阅报表内容，可打印存档

### 5.2.4 日记统计（diary-statistics.html）

- 进入路径：左侧菜单"监理业务 → 日记统计"
- 主要功能：监理日记按项目、时间区间的汇总统计
- 操作步骤：
1. 选择项目与统计时间区间
2. 查看填写数量、审批状态分布等统计结果

### 5.2.5 仪表盘（index.html）

- 进入路径：登录成功后自动进入，或点击左侧菜单"工作台"
- 主要功能：工作台首页，展示项目与业务单据统计、待办事项及各模块快捷入口
- 操作步骤：
1. 登录后进入工作台查看统计卡片与待办
2. 点击统计卡片或快捷入口跳转至对应业务模块
3. 通过顶部导航查看消息与个人信息，可退出登录

### 5.2.6 日志统计（log-statistics.html）

- 进入路径：左侧菜单"监理业务 → 日志统计"
- 主要功能：监理日志按项目、时间区间的汇总统计
- 操作步骤：
1. 选择项目与统计时间区间
2. 查看日志填写与审批情况统计

### 5.2.7 登录 - 监理现场管理系统（login.html）

- 进入路径：浏览器访问系统地址，自动进入登录页（login.html）
- 主要功能：系统登录入口，账号密码认证并签发访问令牌
- 操作步骤：
1. 打开系统地址进入登录页
2. 输入手机号与密码
3. 点击"登录"按钮，认证通过后自动跳转至系统首页（index.html）
4. 认证失败时页面提示错误原因，可重新输入
